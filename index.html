// Multi-agent swarms for the GitHub Copilot app

You didn't sign up to babysit five AI chat tabs.

Wintermute is a plugin for the GitHub Copilot app that plans and runs substantial work as a crew of agent sessions: research, specs, code, investigations and documents. You describe the goal once. It splits the work across child sessions, picks a model for each job, runs independent parts in parallel, and has another session check the work before it counts as done.

Read the plugin docs See how it works
Quick start // install

# 1. Add the marketplace

$copilot plugin marketplace add ncksol/ai_tools

# 2. Install the plugin

$copilot plugin install wintermute@ai-tools

# 3. Start a session

Restart the Copilot app, start a new session, and pick wintermute-core as its agent from the + menu or with /agent. Then describe the work.

Agent ID: wintermute:wintermute-core Runs in the Copilot app

[03 // Comparison]

One session, /orchestrate and Wintermute

The app's built-in /orchestrate already runs child sessions in parallel and stacks PRs; use it when you want to set the workflow yourself. Wintermute packages model choice, independent review and verification into a preset workflow, with a dashboard to follow the whole job. For code work, the difference looks like this:

  One session Built-in /orchestrate Wintermute
Who does the work One main session, which can use sub-agents Child sessions in parallel, with stacked PRs Child sessions in parallel, with stacked PRs
Model and effort The session's model, or Copilot Fusion's pick per step No fixed tier policy; defaults or your instructions Set for every child session from the agent's tier table
Review On demand, or automatically with rubber duck (when enabled) or Fusion No prescribed per-PR review gate; automatic critique is still available A model from another vendor, before every merge
Proof that the tests ran The session's own report No prescribed independent test or CI verification A separate session checks tests, CI and scope at the pushed commit
Final check No prescribed two-judge merge panel No prescribed two-judge merge panel Two judges from two vendors check the last PR
Following the work The transcript The app's project Overview The Overview, plus a dashboard with progress, cost, stuck work and what needs you

Trade-offs: for a small, self-contained task, one session is usually simpler. Even a one-PR swarm adds a review, a claims check and a two-judge panel, which add model calls and cost. Cross-vendor review needs at least two vendors; the default policy uses Anthropic, OpenAI and Google. The checks make independent review happen, but they don't guarantee correct code.

[04 // Swarm dashboard]

Follow the whole swarm in one view

Watch-only · reads Copilot's local data read-only · 127.0.0.1:7927

Needs you

Questions, plans and PRs to approve show on their unit's card and in the header. You answer in the sessions; the dashboard only shows you where to look.

Stuck work

Flags a session that has gone quiet past its limit, keeps failing tool calls or repeats the same call. The detail panel names the rule that fired.

Timeline, Plan, Board

Each session's busy and idle time, the units as a graph of stacked branches, and columns from Planned to Finished.

Cost and History

Cost per session and for the swarm, in dollars at list price. Finished runs keep a summary of time and cost by unit and model.

Privacy: the dashboard reads ~/.copilot/data.db and the session folders and never writes to them. The server listens on 127.0.0.1 only, and its only outbound requests are read-only gh and az queries about the swarm's pull requests. Read the dashboard guide.
